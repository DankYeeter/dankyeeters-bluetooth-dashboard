# D-001 — `:app`-Unit-Tests haengen nach Merge von T-044b

*fehlerdiagnostiker, 23.09.2026, Stand `2099973`; vom Director abgelegt (Rolle ohne Write), inhaltlich unveraendert gekuerzt.*

**Ursache (belegt, Rueckschaltprobe bestanden):** Ein Test stoesst ueber ein
ViewModel einen EQ-Speichervorgang an und endet, bevor der fertig ist.
DataStore 1.1.1 fuehrt den `edit`-Block im Kontext des Aufrufers aus, **waehrend
es die Schreibsperre haelt** (`DataStoreImpl$transformAndWrite$2`:
`coordinator.lock { … withContext(callerContext) { transform } … }`). Aufrufer
ist `Dispatchers.Main` = Robolectric-Main-Looper (`EqViewModel.kt:888`
`viewModelScope.launch { store.save(clean) }`, erreicht ueber
`setVolumeAwareTilt`, `EqViewModel.kt:475`). Der Block liegt noch in der
Main-Warteschlange, wenn der Test endet; Robolectric verwirft sie, Sperre und
serieller Schreibauftrag bleiben fuer immer belegt. Der Store ist JVM-weit
(`EqSettingsStore.kt:20` Delegate, `SystemGraph.kt:68` lazy). Seit `a831c25`
wartet `@Before` in drei EQ-Testklassen per `runBlocking { save(FLAT) }` —
hinter dem toten Auftrag, fuer immer.

**Warum jetzt:** Der gesperrte Store entstand schon auf `3031eb1`, fiel aber nicht
auf (Lesen braucht keine Sperre, liegengebliebene Schreibvorgaenge verschwinden
still). Hypothese, ungeprueft: F-006 ist derselbe Mechanismus.

**Beweis:**
- `jstack` 03:12:47 und 03:16:21 identisch: `SDK 35 Main Thread` parkt in
  `BlockingCoroutine.joinBlocking` ← `EqLayerBypassTest.setUp(:61)`; kein Thread
  in DataStore-/Datei-Code, CPU-Zeit unveraendert.
- Rueckschaltprobe 1 (gleicher Stand, nur Vorgaengertest getauscht): schreibender
  Vorgaenger → Haenger (3/3), nicht schreibender → gruen 6–7 s (2/2).
- Rueckschaltprobe 2: `robolectric.looperMode=INSTRUMENTATION_TEST` → 3/3 gruen.
- `3031eb1` ohne `a831c25`: `:app:testDebugUnitTest --rerun` Exit 0, 529 Tests, 30 s.
- Reproduktion: `--tests '*EqLayerBypassTest' --rerun`, 5/5 Haenger; kleinster
  Fall: `a hold is transient and is not written into the settings` →
  `holding the restoration layer …`.

**Verworfen:** Last durch parallele Laeufe (deterministisch ohne Last);
`AdbdMaskIdentificationTest` (nur letzter Test mit Konsolenausgabe);
Dateisystem-IO (alle IO-Threads untaetig); `runBlocking` blockiert eigenen Block
(ohne schreibenden Vorgaenger gruen).

**Wirkungsbereich:** `eq_settings` belegt; `setup_state` (`SetupStore.kt:17`) und
`hearing_runs` (`AudiogramStore.kt:31`) gleiches Muster, derzeit ruhend.

**Fixrichtung:** Die Schreibsperre eines JVM-weiten DataStore darf nie auf den
Main-Looper angewiesen sein: Speicherfunktionen fuehren `edit` auf eigenem
Dispatcher aus (`withContext(Dispatchers.IO)`, optional injizierbar) —
`EqSettingsStore.save`/`setActiveProfileId`, analog `SetupStore`,
`AudiogramStore`. Reset im `@Before` aus `a831c25` darf bleiben.
**Funktioniert nicht:** `a831c25` zuruecknehmen (Store bleibt still gesperrt);
mehr `idle()`; `runTest` statt `runBlocking`; `@After` mit `runBlocking` auf Main
(Verklemmung); weniger Parallelitaet.

**Regressionstest:** (1) `EqLayerBypassTest` ganz und als Paar gruen in
Sekunden (heute 5/5 Haenger). (2) Neu, reihenfolgeunabhaengig: `EqViewModel`
erzeugen, `idle()`, `setVolumeAwareTilt(true)` **ohne** `idle()`, sofort auf Main
`runBlocking { withTimeout(5_000) { SystemGraph.settingsStore.save(FLAT) } }` →
muss zurueckkehren (heute abgeleitet: Timeout, nicht gemessen).
