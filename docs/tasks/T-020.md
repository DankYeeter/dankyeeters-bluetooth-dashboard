## Der Kern: QA-010 ist die Wurzel, pruefe sie zuerst

Dein Befund war, dass es **drei getrennt gepflegte Kopien** der Verlust-
definition gibt und dass eine Mutation an `hasLoss` **keinen** Panel-Test
bricht. Der `developer` hat daraus **eine** Definition gemacht:

- neu `enum class TxLossChannel { DROPPED_PACKETS, STACK_DROPOUTS }` in
  `LinkLiveModels.kt` — nur Bezeichner, keine Anzeigetexte
- neu `A2dpTxDelta.lossByChannel: Map<TxLossChannel, Long>` — **die**
  Definition; `hasLoss` und `lossCount` leiten sich daraus ab
- die App-Erweiterung `lossCount()` in `LiveTraceModel.kt` ist **entfallen**
- `LossRow` baut nichts mehr nach, sondern iteriert `lossByChannel` und
  uebersetzt ueber einen **exhaustiven `when`** im app-Modul

**Die Zusage, die du pruefen sollst:** Ein neuer Kanal im `core-monitor`
**kompiliert nicht**, bevor die Oberflaeche ein Wort dafuer hat.

**Sein Mutationsnachweis, den du nachfahren sollst:** Zeile
`TxLossChannel.STACK_DROPOUTS to dropouts,` in `LinkLiveModels.kt` streichen →
erwartet werden **fuenf** Fehlschlaege ueber **drei** Pfade:
`A2dpTxProbeTest :: stack dropouts alone are loss`,
`LiveLinkSourceTest :: a window of stack dropouts names that channel and not
the underflows`, `MonitorTraceModelTest :: a window of stack dropouts alone
puts a mark on both channels`, `MonitorTraceModelTest :: the close-up counts
the stack's loss only`, `LiveLinkPanelScreenTest :: a window of stack dropouts
alone names that channel`.

Analog fuer `DROPPED_PACKETS`. **Faellt weniger als das, ist die Kopplung
nicht so dicht wie behauptet — und das ist der wichtigste moegliche Befund
dieses Retests.**
