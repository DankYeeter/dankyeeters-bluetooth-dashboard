# T-069 — SR-040: 0-Byte-Ledger liest als "nie geschrieben" (developer)

Es gilt der Rahmen aus `~/.claude/agents/_rahmen.md`. Projektzeilen in der
`CLAUDE.md` des Projekts. Abweichung: Arbeit im Worktree `C:\t069`, Branch
`t069`, Basis `367afda` (vom Director angelegt, `local.properties` kopiert).
Kein Geraet.

**Ziel:** Eine auf 0 Byte gekuerzte Ledgerdatei liest als **unlesbar**
(wie ein korrupter Ledger nach AD-042), nie als leeres, nie geschriebenes
Ledger — damit der Rueckweg nicht still verloren geht.

**Stufe/Modus:** normal (Unterscheidung 0 Byte vs. nie angelegt ist ein
Entwurfsschritt).

**Befund (security/findings.md, woertlich):** "SR-040 | 0-Byte-Ledgerdatei
liest als nie geschrieben (M3-Luecke, `SettingsLedgerStoreTest.kt:203`); nur
durch Dateisystemschaden/Root | niedrig". Nutzerentscheid 29.09.: **beheben**.
Am Geraet bestaetigt (T-066a, `docs/berichte/T-066a-qa-engineer.md`
"Punkt 6"): Datei `files/datastore/settings_ledger.preferences_pb` auf 0 Byte
→ kein Banner, keine "unlesbar"-Meldung; Rueckweg danach mit falschem Vorwert
(1001 statt 1000), LDAC-Stufe blieb auf 330.

**Stellen:** `SettingsLedgerStore` `core-system/.../devices/SettingsLedger.kt:142`;
Test `app/src/test/.../SettingsLedgerStoreTest.kt:201-206` dokumentiert das
heutige Verhalten ("not a choice of this app") — der Test wird umgedreht, nicht
geloescht. Bestehende Vorgaben AD-042 V9/V10 (Test Z. 187-199): korrupt liest
als Fehler, ist verwerfbar.

**Vorgaben:** Ponytail — kleinste Loesung, keine neue Abhaengigkeit. Eine
frisch installierte App (Datei existiert nicht) muss weiterhin als leeres
Ledger lesen. Vorlauf: kein Ausloeser (Dateizugriff nur innerhalb des
App-Verzeichnisses; Befund stammt selbst vom security-reviewer).

**Test:** 0-Byte → `entries().isFailure`; Datei fehlt → `success(emptyList())`;
Suite am Ende, Zahl und Uhrzeit in den Bericht.
