# T-045 — Bestandsaufnahme AK-8 bis AK-16 gegen den Code (architect)

**Ziel:** Für die nächste Entwicklung steht fest, welche Kriterien der Säulen
1–3 gebaut, teilweise gebaut oder offen sind. Für das Offene liegt ein Schnitt
in lauffähige Schritte vor. Die QA-Stichprobe in T-043a meldete dazu: „Den
geführten Prozess AK-12..16 gibt es im Code noch nicht, grep ‚Ausweichen' ohne
Treffer.“

**Abnahmekriterien:** AK-8 bis AK-16, wörtlich in `GOAL.md` Z. 68–127.

**Stand:** Branch `auto/2026-09-23`. Parallel arbeiten zwei developer in
eigenen Worktrees (T-044: Beobachtungslauf, EQ-Tests). Du liest nur und
änderst keinen Code.

## Auftrag (Entscheidungstiefe: Bestandsaufnahme + Schnitt)

1. Je Kriterium AK-8..AK-16 ein Urteil: **gebaut / teilweise / offen**. Belege
   es mit Datei:Zeile oder mit einer Suche, die leer blieb. Bei leerer Suche
   eine zweite Suche mit anderer Wortwahl (K-1).
2. Für jedes Kriterium mit „teilweise“ oder „offen“: der kleinste Schritt, der
   etwas Lauffähiges hinterlässt. Dazu die Angabe, ob der Schritt
   - das Gerät braucht,
   - einen neuen Helfer-Befehl braucht (dann gelten AK-10 und der
     Security-Vorlauf),
   - eine UI-Spec braucht,
   - eine Entscheidung des Nutzers braucht.

   Grundlagen: `docs/research/R-010*` und
   `docs/archiv/state-messbefunde-2026-09-03.md` (dort die sechs Massnahmen,
   der BQR-Kanal, das Zähler-Inventar und der Abschnitt „Gesetzt heisst NICHT
   gebaut“).
3. Welche Fragen muss der Nutzer beantworten, bevor Säule 3 gebaut werden
   kann? Höchstens fünf, jede mit einer Empfehlung.

**Berührt Dateien:** nur `docs/berichte/T-045-architect.md` (neu). Einen
AD-Eintrag in `ARCHITECTURE.md` nur, wenn eine Entscheidung fällig ist, die
nicht beim Nutzer liegt. Kein Commit.

## Rückgabe

Kontraktblock plus höchstens dreissig Zeilen. Die Tabelle je Kriterium steht
in der Berichtsdatei.
